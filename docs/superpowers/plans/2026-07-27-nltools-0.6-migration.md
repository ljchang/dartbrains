## 3. The one decision that needs your call: `.iplot()`

**This is the highest-risk item and it is a content decision, not a mechanical fix.**

In 0.5.1, `iplot()` returned nilearn's HTML viewer. Confirmed in the current build — `_site/GLM_Single_Subject_Model/index.html` contains `<iframe srcdoc="&lt;!doctype html...">`, a fully self-contained interactive viewer baked into the static page.

In 0.6, `iplot()` is rebuilt on **niivue** (`ipyniivue`, WebGL, anywidget) and returns an `ipywidgets.VBox`. Upstream states plainly: *"`iplot` is live-kernel only (Jupyter, marimo). It does not render in statically-built docs — use `BrainData.plot()` there."*

dartbrains has **22 `.iplot()` calls across 6 build-executed notebooks.** They will not render. Three options:

| Option | Cost | Result |
|---|---|---|
| **A. `.iplot()` → `.plot()`** (recommended) | Low, mechanical | Static figures. Loses interactivity the course currently has. `plot(method='glass'\|...)` is the drop-in. |
| **B. Move those notebooks to `mode: wasm`** | High | Keeps interactivity, but means nltools + niivue + nibabel + nilearn booting in Pyodide, plus dataset seeding for every affected chapter. The existing WASM chapters were kept deliberately light for exactly this reason. |
| **C. Hybrid** | Medium | `.plot()` everywhere in the narrative; keep 1–2 `iplot()` showcase cells and mark those chapters `mode: wasm`. |

My read: **A for the whole course, with the `iplot()` API mentioned in prose** ("in a live notebook you can call `.iplot()` for an interactive WebGL viewer with atlas overlays") so students learn it exists without the build depending on it. Revisit B only if losing the interactive viewer measurably hurts the chapters that lean on it (`Connectivity.py` has 7 calls and uses them to explore whole-brain connectivity maps).

Note the API also changed: `view='surface'` → `view='render'`, `anatomical=` → `bg_img=`, and `mode=`/`units=`/`cut_coords=`/`symmetric_cmap=` are gone.

## 5. Substantive rewrites

### 5.1 GLM: `.regress()` → `.fit(model='glm')`

`.regress()` is **removed outright** — it raises `AttributeError`, no shim. 6 call sites (`Connectivity` ×3, `GLM_Single_Subject_Model`, `Group_Analysis`).

```python
# OLD
smoothed.X = dm
stats = smoothed.regress()
beta = stats['beta']

# NEW
smoothed.fit(model='glm', X=dm)
beta = smoothed.glm_betas      # also .glm_t .glm_p .glm_se .glm_residual .glm_r2
```

This is a clear teaching improvement — sklearn-style, and the design matrix is passed explicitly instead of being smuggled in through `.X`.

Downstream fixes that ride along:
- `Group_Analysis.py:377,381` — `stats['beta'].write(...)` → `data.glm_betas.write(...)`.
- `Connectivity.py:403` — the `np.where(smoothed.X.columns == 'vmpfc_motor')[0][0]` index dance becomes `smoothed.compute_contrasts('vmpfc_motor')`. Much better pedagogy: named contrasts instead of column-index archaeology.

### 5.2 DesignMatrix is now Polars-backed

This is the change most likely to produce silent breakage, because pandas idioms fail in different ways.

- **`.loc` / `.iloc` are gone.** Affects `Connectivity.py:377` (`dm_1.loc[:, motor_variables].sum(axis=1)`), `GLM_Single_Subject_Model.py:332` (`dm_conv_filt.iloc[:,10:].plot()`), and `Introduction_to_ICA.py` lines 127/130/254/257/258/… — the ICA notebook builds its simulated FFA/PPA signals entirely through `.iloc[array] = value` assignment. That block needs a genuine rewrite (build the signal in numpy, then wrap in `DesignMatrix`).
- **`.reset_index()` is gone** — no Polars equivalent, just delete the call. Only site is inside `Connectivity.py`'s `load_bids_events` helper, which is itself being deleted (§5.3).
- **`.convolved` and `.confounds` are read-only.** Direct assignment raises `AttributeError`. Affects `Connectivity.py:295,383,571` and `GLM_Single_Subject_Model.py:198`. Use `.append(..., as_confounds=True)` — verified: appending a raw pandas frame auto-registers its columns as confounds.
- **`.polys` → `.confounds`**, `exclude_polys=` → `exclude_confounds=`, and the `polys=` constructor kwarg → `confounds=` (`Connectivity.py:371`).
- Column access returns a **Polars** Series: `.values`/`.tolist()` → `.to_numpy()`/`.to_list()`. Worth an explicit callout in `GLM_Single_Subject_Model` prose since the course teaches "Design_Matrix is built on pandas DataFrames" (`GLM_Single_Subject_Model.py:125`) — that sentence is now wrong and should point at the Polars intro chapter instead. **This is actually a nice cross-link**: `Introduction_to_Polars.py` already exists in the curriculum, so the GLM chapter can now say "this is the Polars API you just learned."

### 5.3 `onsets_to_dm` → `DesignMatrix(events_path, ...)`

`nltools.file_reader` is gone; the functionality folded into the constructor.

```python
# OLD
from nltools.file_reader import onsets_to_dm
dm = onsets_to_dm(onsets, run_length=n_tr, TR=tr, hrf_model=None)

# NEW — boxcar (convolve as a separate teaching step, as the course does)
dm = DesignMatrix(events_path, run_length=n_tr, TR=tr, hrf_model=None)

# NEW — default: HRF-convolved in one call, matching nilearn's default
dm = DesignMatrix(events_path, run_length=n_tr, TR=tr)
```

`GLM_Single_Subject_Model.py` deliberately passes `hrf_model=None` so convolution can be taught as its own step — that pedagogy is preserved exactly, which is good.

**The big win**: `Connectivity.py:355-371` carries a hand-rolled `load_bids_events()` helper whose docstring says it *"Bypasses nltools.onsets_to_dm because that wrapper has a column-name mangling bug when TR is supplied."* That bug is fixed. **Delete the whole helper** and call `DesignMatrix(events_path, run_length=n_tr, TR=tr, hrf_model=None)`.

Also verified: `.convolve()` now **always** suffixes `_c{i}` and drops the source column, consistently. `GLM_Single_Subject_Model.py:196-198` has a comment-plus-fixup working around the old inconsistency — delete both.

### 5.4 The PPI cell (`Connectivity.py:341-405`)

The single hardest migration, and upstream wrote a worked example for exactly this flow (`migration-guide.md` §"Worked example: PPI"). The rewrite collapses the custom loader + `pd.concat` + manual `.convolved` re-assertion into:

```python
events = DesignMatrix(events_path, run_length=n_tr, TR=tr, hrf_model=None)
task = (events
        .with_columns(motor=pl.sum_horizontal(motor_variables))
        .drop(motor_variables)
        .convolve())
task = task.with_columns(vmpfc=vmpfc_signal).with_columns(
    vmpfc_motor=pl.col('vmpfc') * pl.col('motor_c0'))
dm = task.append([csf, mc_cov, spikes], axis=1, as_confounds=True) \
         .add_poly(order=2, include_lower=True)
```

`dm.convolved` and `dm.confounds` stay correct automatically — no manual re-assertion. This is strictly better material for teaching PPI: the interaction term now reads like the equation.

### 5.5 `.predict()` — new signature, `Predict` dataclass (`Multivariate_Prediction.py`)

```python
# OLD
svm_stats = data.predict(algorithm='svm',
                         cv_dict={'type':'kfolds','n_folds':5,'subject_id':subject_id},
                         **{'kernel':'linear'})
weight_map = svm_stats['weight_map']

# NEW
from sklearn.model_selection import GroupKFold
res = data.predict(y=Y, model=SVC(kernel='linear'), cv=GroupKFold(n_splits=5), groups=subject_id)
res.weight_map, res.scores, res.mean_score, res.predictions, res.fold_weight_maps
```

Three gotchas, all verified empirically:

1. **`**kwargs` passthrough is gone.** `predict(algorithm='svm', **{'kernel':'linear'})` → pass a constructed estimator: `model=SVC(kernel='linear')`. Same for `alpha=0.01`, `class_weight='balanced'`.
2. **⚠️ `groups=` is silently ignored when `cv` is an int.** `predict(y=..., cv=5, groups=subject_id)` runs `StratifiedKFold` and warns `"The groups parameter is ignored by StratifiedKFold"` — you get *non*-subject-wise folds. To reproduce the course's subject-wise CV you must pass a splitter: `cv=GroupKFold(n_splits=5)` or `cv=LeaveOneGroupOut()`. Both verified working. **This is the most dangerous item in the migration** — it fails quietly and inflates accuracy.
3. Algorithm names: `'ridgeClassifier'` → `'ridge_classifier'`; `'ridgeCV'`/`'lassoCV'` have no string shortcut — pass `RidgeCV()`/`LassoCV()`.

Also check what `Multivariate_Prediction.py:205` documents as `dist_from_hyperplane_all` — the `Predict` dataclass exposes `['predictions','scores','mean_score','std_score','cv_folds','weight_map','fold_weight_maps','estimator']`, so that prose needs rewriting (derive it from `res.estimator.decision_function(...)`, or use `plot_dist_from_hyperplane`).

**Opportunity**: `Multivariate_Prediction.py:279,343` does `data.apply_mask(motor).predict(...)` to run an ROI-restricted model. 0.6 has `spatial_scale='roi'` / `'searchlight'` with `roi_mask=` built in — the course could teach the searchlight/ROI/whole-brain spatial-scale axis (Jolly & Chang 2021) as a first-class concept instead of a masking trick.

### 5.6 `.ttest(threshold_dict=)` (`Thresholding_Group_Analyses.py`)

`threshold_dict=` is gone. New signature: `ttest(*, popmean=0.0, permutation=False, n_permute=5000, tail=2, ...)` returning `{'mean','t','z','p'}` (verified).

```python
# OLD
con1_stats = con1_dat.ttest(threshold_dict={'unc': 0.001})
con1_stats = con1_dat.ttest(threshold_dict={'fdr': 0.05})

# NEW — thresholding is now an explicit, separate step
from nltools.stats import threshold, fdr
res = con1_dat.ttest()
t_unc = threshold(res['t'], res['p'], thr=0.001)
t_fdr = threshold(res['t'], res['p'], thr=fdr(res['p'].data, q=0.05))
```

For a chapter whose entire subject is multiple comparisons, **separating "estimate" from "threshold" is pedagogically better than the old `threshold_dict` blob**, and `permutation=True` gives a third, non-parametric option to teach alongside unc/FDR. Worth restructuring the chapter around, not just patching. Note `fdr()` returns `-1` when nothing survives — the notebook should handle that case explicitly (it's a teachable moment).

`.ttest2(other)` is new — `Group_Analysis.py:485` currently does a paired test by subtracting and running a one-sample test, which is still correct; mention `ttest2` for the independent-samples case.

### 5.7 RSA — the biggest pedagogical win (`RSA.py`)

The course currently: loops over 50 ROI masks, applies each mask, computes a distance matrix, stashes in a list, loops again to convert distance→similarity, loops again to correlate against the model RDM, then paints results back with `roi_to_brain`. That's ~5 cells of bookkeeping around ~2 lines of actual RSA.

0.6 collapses it:

```python
rdms = beta.distance(metric='correlation', spatial_scale='roi', roi_mask=mask)
brain_map = rdms.similarity(motor_rdm, metric='spearman', project=True)
```

Verified: `distance(spatial_scale='roi')` returns a stacked `Adjacency` `(n_rois, n_cond, n_cond)` carrying `spatial_scale` provenance, and `similarity(..., project=True)` paints per-ROI scalars straight back to a voxel-space `BrainData`.

I'd keep the explicit loop **as the teaching device** (it's how you learn what RSA does) and then show the one-liner as "here's how you'd actually write it" — that contrast is genuinely good teaching, and it's what the chapter's structure already implies.

⚠️ **One caveat found while testing**: if any parcel yields a degenerate RDM (all-NaN — e.g. a parcel with no data coverage), `similarity(..., method=None)` raises `ValueError: All values are NaN after pairwise removal` rather than warning and skipping. The permutation path (`n_permute=...`) warns and proceeds. Test on the real localizer betas before committing to the one-liner; if it trips, file upstream.

### Watch for during the build

- `.add_dct_basis()` now adds a constant by default (`include_constant=True`). `GLM_Single_Subject_Model.py:326,338` chains `.add_dct_basis(duration=128)` then `.add_poly(order=2, include_lower=True)`, which now emits `UserWarning: Design Matrix already has an intercept column...skipping poly_0`. Harmless but confusing on a student's screen — pass `include_constant=False` or reorder.
- `BrainData` auto-detects and resamples to a template mask on construction. Any cell asserting a voxel count will change.
- `.smooth()` / `.standardize()` now **return copies** instead of mutating in place. `ICA.py:93-94` and `Group_Analysis.py:366` already assign the result, so they're fine — but grep for any bare `data.smooth(6)` statement whose result is discarded.
